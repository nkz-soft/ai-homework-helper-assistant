**Add minimal Web UI (FastAPI + Jinja2 + HTMX)**
  - **Tech stack**
    - Backend: FastAPI
    - Templates: Jinja2
    - UI interactivity: HTMX (no build step)
    - Styling: simple CSS (or PicoCSS via CDN, optional)
    - Transport: regular POST (optionally upgrade to SSE later)

  - **Scope**
    - Single-page chat UI served from the same FastAPI app.
    - No authentication, no persistence (in-memory conversation on the client only).
    - Uses existing endpoint `POST /api/v1/chat`.

  - **Files to create**
    - `apps/assistant_api/src/ui/__init__.py`
    - `apps/assistant_api/src/ui/routes.py` (UI router)
    - `apps/assistant_api/src/ui/templates/chat.html` (main page)
    - `apps/assistant_api/src/ui/templates/_messages.html` (partial for messages list)
    - `apps/assistant_api/src/ui/static/app.css` (minimal styles)
    - (optional) `apps/assistant_api/src/ui/static/app.js` (only if needed; avoid if HTMX is enough)

  - **Implementation steps**
    1. **Enable templates + static files in FastAPI**
       - Mount `/static` to serve `app.css`.
       - Add Jinja2Templates pointing to `ui/templates`.

    2. **Add UI routes**
       - `GET /` → renders `chat.html`
       - `GET /ui` (alias) → renders `chat.html`
       - `POST /ui/chat` → calls internal function/client to hit `POST /api/v1/chat` and returns an HTML partial (`_messages.html`) with updated chat.

    3. **Build the HTML page**
       - Layout: header + messages container + input form.
       - HTMX form:
         - `hx-post="/ui/chat"`
         - `hx-target="#messages"`
         - `hx-swap="innerHTML"` (or `beforeend` if returning only last message)
       - Add a “loading” indicator using `hx-indicator`.

    4. **Server-side message model for rendering**
       - Define a minimal schema:
         - `Message(role: "user"|"assistant", content: str)`
       - For v1 (no persistence): keep messages in hidden input as JSON, or simplest:
         - keep only last user message + assistant answer rendered, or
         - keep messages in a short-lived server session (in-memory dict keyed by random `chat_id` cookie).  
       - Recommended for minimal UI: **client-only history** (hidden JSON) to avoid server state.

    5. **Wire to the API**
       - UI POST handler takes user text, calls `/api/v1/chat` with `{question, context}`.
       - Render assistant answer + citations beneath.
       - If API returns diagnostics, show in a collapsible `<details>` block.

    6. **Basic UX**
       - Auto-scroll messages container to bottom (optional tiny JS).
       - Disable submit while request is running (HTMX indicator + button disabled via CSS class).
       - Handle errors: show a red “Request failed” message.
